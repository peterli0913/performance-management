# TJ4 表格自动化工具集

凯莱英 TJ4 生产部表格处理工具。当前实现第一个功能：**安全质量奖人员对账**——
上传人员清单与安全质量奖核算数据，自动比出四类差异人员，人工复核后生成保留原格式与公式的新核算表。

## 快速开始

```bash
pip install -r requirements.txt
streamlit run app.py
```

首次打开会自动载入仓库里的两个示例文件，可以直接看到完整效果。

## 界面流程

| 步骤 | 说明 |
| --- | --- |
| 上传 | 多选文件，或把整个文件夹打成 `.zip` 上传（自动递归展开，支持 xlsx/xls/csv/docx/pdf） |
| 综合数据库 | 所有文件的所有子表合并进一个 SQLite：每个子表一张表，另有 `_files`/`_sheets`/`_documents`/`_problems` 元数据表，可写 SQL 交叉查询，也可下载 `.db` |
| 车间映射 | 「目前分组」到「车间」的对应关系，带置信度，可手工改，也可选择新建车间块 |
| 四类复核 | 每类一个页签，两种复核方式：「表格批量」勾选，或「逐条按钮」每人一组*应用修改*/*取消*按钮 |
| 生成核算表 | 两个导出按钮，见下 |

每个人有三种状态，**应用**和**取消**是两个独立开关：

| 状态 | 含义 |
| --- | --- |
| 应用 | 纳入「已应用版」导出（也在「对照标记版」里） |
| 取消 | 从**两个**导出里都剔除 |
| 待定（默认） | 只出现在「对照标记版」里 |

## 判定规则

以人员清单「生产部」子表中**职务**为 助工（助理工程师）/操作工/工程师/班长 的人员为基准，
与核算数据「一线人员」子表按 **姓名 + 员工编号** 双匹配。参照日期默认从清单文件名解析
（`…，07-31-2026.xlsx` → `2026-07-31`）。

| 分类 | 条件 |
| --- | --- |
| **新入职员工** | 清单有、核算无，且入职时间在参照日期前一个月内；**或**出现在「人员变动说明」且离职时间为空 |
| **待定·清单有核算无** | 清单有、核算无，但不满足上面的条件 |
| **离职人员** | 核算有、清单无，且在「离职人员&调出人员」子表；**或**在「人员变动说明」且有离职时间 |
| **待定·核算有清单无** | 核算有、清单无，但查不到离职记录 |

每条结果都带**判定依据**（命中了哪个子表的第几行、比较了哪个日期），以及必要的**提示**：

- 已在「副主任&工艺组长及其他」子表（默认排除，避免一人两处）
- 仍在「生产部」但职务已不是目标职务（多为晋升，如班长→工艺组长）
- 员工编号相同但姓名不一致 / 姓名相同但编号不一致（数据质量问题，不当成"一增一减"）

示例文件的实际结果：两表一致 616 人，新入职 213 人，待定·需新增 47 人，离职 41 人，
待定·需核实 16 人，已在其他子表 59 人。

## 两种导出

| 按钮 | 行为 |
| --- | --- |
| **对照标记版** | 全量对照。新增人员插到对应车间**最下方**，姓名与员工编号填**绿色**；需删除的人员**保留原行**，姓名与员工编号填**红色**。被点「取消」的人不纳入 |
| **已应用版** | 只处理被点「应用修改」的人：删除类**直接删行**，新增类**直接插入对应位置**，不着色 |

两者都保留原文件的**全部子表、字体、行高列宽、公式、自动筛选、条件格式**，
只改动「一线人员」子表的人员行；打开后 Excel 会自动重算。

## 为什么不用 openpyxl 存盘

示例核算文件里有 openpyxl 保存时会**丢弃**的部件：

- `xl/externalLinks/` —— 「副主任&工艺组长及其他」子表有 128 个 `VLOOKUP(…,[1]生产部!$C:$C,…)` 依赖它
- `xl/printerSettings/`、`xl/customProperty*.bin`、`xl/drawings/vmlDrawing*.vml`（批注框）

所以 `tj4tools/xlsx_surgery.py` 直接改写 OOXML 的 XML 部件，未修改的部件逐字节原样复制。
行号变化时会重映射：公式引用（跳过他表与外链引用）、合并单元格、条件格式 `sqref`、
`autoFilter`、`dimension`、`definedNames`（`_FilterDatabase` / `Print_Area`），
并把 675 处共享公式展开成普通公式。

区间终点用了单独的映射语义：车间块末尾追加人员时，块内区间（`COUNTIF($L$3:$AP$73,"a")`、
合并区 `A3:A73`）和跨全表区间（`SUM(F3:J675)`、打印区域）都要顺延，否则新人会落在统计范围外。

## 代码结构

```
app.py                      Streamlit 界面编排（零业务逻辑）
tj4tools/
  normalize.py              姓名/编号/日期规范化（零宽字符、姓名带编号后缀、"--" 占位）
  ingest.py                 文件/文件夹/zip → 表格与文档（防目录穿越、GBK 文件名、表头探测）
  db.py                     入库到 SQLite
  roster.py                 领域解析 + 四类判定 + 车间映射
  xlsx_surgery.py           保格式的 xlsx 行插入/删除/着色
  bonus_export.py           两种导出的编排
tests/                      94 项测试，全部基于仓库里的真实文件
.cursor/skills/             5 个配套 skill
```

## 测试

```bash
pip install pytest
python -m pytest tests/ -q
```

不需要起浏览器，也不需要人工看截图。测试全部使用仓库里的真实文件做黄金样本，包含：

- 规范化与日期解析边界
- 公式行号重映射（函数名不被误认为单元格、字符串字面量不被改写、他表/外链引用不动）
- 四类判定的守恒关系与已知个体的分类
- 导出后的结构体检：行号唯一升序、单元格引用与所在行一致、合并区不重叠、
  `count` 属性正确、`sharedStrings` 未被改动、`calcChain` 及其 Override/Relationship 都已移除、
  所有 XML 部件格式合法、除 `calcChain` 外没有丢失任何部件
- `AppTest` 端到端跑通整个界面并生成 Excel，包含两条回归：
  勾选「应用」后多次 rerun 决策不能丢；界面预览的人数必须等于生成结果里的人数

## 部署到 Streamlit Community Cloud

1. 推送本仓库到 GitHub。
2. 新建 App，主文件填 `app.py`，依赖用 `requirements.txt`。
3. 上传上限已在 `.streamlit/config.toml` 调到 500MB。

容器文件系统是易失的，所有中间结果都在内存 `BytesIO` / 内存 SQLite 里，不会往仓库写文件。
