# 两表人员/台账对账

## 铁律

```
先量化差异规模，再写分类逻辑。
```

原始 diff 出来几百条时，**几乎一定是漏了一个数据源或一个过滤条件**，不是真有几百条异常。
先按各种维度（分组、职务、入职年份、是否出现在第三个子表）交叉统计，找出差异的结构。

## 键规范化清单（漏一条就产生假差异）

真实中文表格里踩过的坑，按出现频率排：

| 现象 | 处理 |
| --- | --- |
| `曹\u200b睿\u200b晟` 零宽字符 | 删 `\u200b\u200c\u200d\ufeff\u2060` |
| `田志勇\xa0` 不换行空格 | `\xa0` → 普通空格再 strip |
| `王鑫（ALS8215）` 姓名带编号后缀 | 剥掉尾部 `(...)`/`（...）` |
| `张志强(ALS15906)` 半角括号 | 同上 |
| 编号大小写/前后空格 | `.strip().upper()` |
| 全角字母数字 | `unicodedata.normalize("NFKC", s)` |
| `--` / `放弃入职` 当日期 | 归一为 None，并保留原文到备注 |
| 日期时而 `datetime` 时而 `2026/07/29` 字符串 | 统一 parser |

## 匹配策略

主键用"姓名+编号"双匹配，但**必须额外报出两类近似匹配**，它们是数据质量问题而不是真差异：

- 编号相同、姓名不同 → 很可能改名或录错字
- 姓名相同、编号不同 → 很可能重名或调编制

把它们作为标记附在结果行上，让业务方判断，不要静默合并、也不要当成"新增+离职"两条。

## 分类映射靠数据推，不靠猜

当 A 表的分组（60 种细粒度）要映射到 B 表的车间（12 种粗粒度）时：

1. **经验映射**：先取两表已匹配上的人，统计 `(A分组, B车间)` 共现，取众数。这是最可信的。
2. **规则兜底**：只给经验映射覆盖不到的分组用正则（如 `X（Y委培）` → 映射到 Y）。
3. **人工可改**：界面上把映射表暴露成可编辑表格，并标出"低置信"（样本数少或众数占比低）的行。

只写规则不做经验映射，等于把业务方脑子里的隐性规则硬编码，下个月就错。

## 判定要留痕

每条结果都带上"判定依据"字段（命中了哪个子表的哪一行、比较了哪个日期），
业务方复核时才不用回头翻原表。这比多加几个分类更有价值。

## 便宜的验证

用真实文件做黄金样本断言，而不是造假数据：

```python
def test_known_people():
    r = reconcile(REAL_A, REAL_B)
    assert r.category_of("周圣玮", "ALS18092") == "新入职员工"   # 变动说明里有、离职时间空
    assert r.category_of("王子睿", "ALS15643") == "离职人员"     # 离职表里有离职时间
    assert r.counts["新入职员工"] + r.counts["待定"] == r.counts["仅清单有"]
```

再加一条守恒断言：`四类人数之和 == 两侧差集之和`。它能抓住绝大多数逻辑回归。
